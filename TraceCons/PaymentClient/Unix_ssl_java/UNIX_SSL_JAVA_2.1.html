Java Integration Examples

This is an example of a Java integration to the Payment Client for the SSL+ Payment Gateway.

Before you start

Step 1. The following assumptions are made:

    • You have Java installed on your server
    • Your Web Server is configured to use Java servlets, and the servlet engine's classpath points to both the Payment Client classes directory (eg /usr/local/QSIPayments/PaymentClient/classes) and the Web Server's servlet directory (eg /home/httpd/servlet).
    • You have permissions to create directories and execute shell scripts (root user is recommended)
    • The Payment Client has been installed

Step 2. You will need the following information prior to the install:

    • Web Server servlet directory
    • HTML file directory (eg. /home/httpd/html)

Installing Perl integration examples

Step 3. Running the shell script
    • Copy the "UNIX_SSL_JAVA_2.1.tar.gz" file into a temporary directory
    • Untar the "UNIX_SSL_JAVA_2.1.tar.gz" file (eg. gzip -d < UNIX_SSL_JAVA_2.1.tar.gz | tar xf -)
    • Run the installation shell script "JavaInterface.sh" (eg. sh JavaInterface.sh)
    • At the prompts enter the information you have gathered at Step 2

Running the Perl Interface

Step 4. Running the Perl example
    • Once the installation of the Java Payment Client Interface is complete and the web server is configured to execute Java servlets, you should be able to run the example that uses the Java Interface. This should be able to start from the following URL: http://localhost/Java_SSL_Order.html

How to use the examples in your Shop & Buy

Before integrating into your Shop & Buy it is important to understand the message flow of the files contained within the package. Once the Java_SSL_Order.html file's form is completed, the following steps occur:

    • The form submits the field values to SSL_DO_Servlet (DO - stands for Digital Order).
    • This servlet will make calls to the Payment Client, which takes care of encryption and messaging to the Payment Server.

NOTE : For the integrator much of this logic is hidden. The servlet source is well documented to show the basic method of initializing a payment.

Logical flow through an SSL Payment process:

    • Creating a PaymentClient instance
    • Sending a getDigitalOrder call
    • Closing the instance
    • Taking an encrypted DR (Digital Receipt)
    • Creating a PaymentClient Instance
    • Then use the getDigitalOrder called to decypt it.
    • Closing the instance

For further information refer to the in-code documentation and the Payment Client Manual.
