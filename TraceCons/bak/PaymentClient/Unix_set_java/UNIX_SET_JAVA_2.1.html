Java Integration Examples

This is an example of a Java integration to the Payment Client for the SET Payment Gateway. This is a transaction which is processed using the Secure Electronic Transaction (SET) architecture.

Before you start

Step 1. The following assumptions are made:

    • You have Java installed on your server
    • Your Web Server is configured to use Java servlets, and the servlet engine's classpath points to both the Payment Client classes directory (eg /usr/local/QSIPayments/PaymentClient/classes) and the Web Server's servlet directory (eg /home/httpd/servlet).
    • You have permissions to create directories and execute shell scripts (root user is recommended)
    • The Payment Client has been installed
    • Your merchant record at the Bank has the following configuration:
      • Merchant granted privilege 'SET'.

Step 2. You will need the following information prior to the install:

    • Web Server servlets directory (eg. /home/httpd/servlet)
    • HTML file directory (eg. /home/httpd/html)
    • The preferred transaction type for your SET transactions (either Sale or Auth)
    • Your Merchant Shop ID (eg 12345678955)
    • The host address of your SET helper (ie IP Number or IP Name)
    • The port number of your SET helper (eg 11257)
    • The MPOS (Merchant Point of Sale) Wakeup URL (eg http://<domain>:10257/)
    • The MPOS Transaction URL (eg http://<domain>:257/)
    • The URL for SET transactions (eg http://<webserver_domain>/servlet/SET_Transaction_Servlet?sessionId=[TRANSID])
    • The URL for SET transaction failure notices (eg http://<webserver_domain>/Java_SET_Order.html)
    • The URL for SET transaction success notices (eg http://<webserver_domain>/Java_SET_Order.html)

Installing Java integration examples

Step 3. Running the shell script
    • Copy the "UNIX_SET_JAVA_2.1.tar.gz" file into a temporary directory
    • Untar the "UNIX_SET_JAVA_2.1.tar.gz" file (eg. gzip -d < UNIX_SET_JAVA_2.1.tar.gz | tar xf -)
    • Run the installation shell script "SET_JavaInterface.sh" (eg. sh SET_JavaInterface.sh)
    • At the prompts enter the information you have gathered at Step 2

Running the Java Interface

Step 4. Running the Java example
    • Once the installation of the Java Payment Client Interface is complete and the web server is configured to execute Java servlets, you should be able to run the example that uses the Java Interface. This should be able to start from the following URL: http://localhost/Java_SET_Order.html

How to use the examples in your Shop & Buy

Before integrating into your Shop & Buy it is important to understand the message flow of the files contained within the package. Once the Java_SET_Order.html file's form is completed, the following steps occur:

    • The form submits the field values to SET_DO_Servlet (DO - stands for Digital Order).
    • This file will make a call to the Payment Client, which will request a SET wakeup message from the MPOS.
    • The MPOS will return a SET wakeup message to SET_Start_Servlet.
    • SET_Start_Servlet displays a message indicating that a payment is in progress and it sends the wakeup message to SET_Wakeup_Servlet.
    • SET_Wakeup_Servlet will receive this message and invoke the customer's wallet. When the customer processes a payment using their wallet the response is caught by SET_Transaction_Servlet.
    • SET_Transaction_Servlet brokers a payment initialisation with the MPOS and provides the link between the customer and the MPOS for subseqent messages.

NOTE : For the integrator even more logic is hidden. The servlet source is well documented to show the basic method of initializing a SET payment.

Logical flow through a SET Payment process:

    • Creating a PaymentClient instance
    • Sending a getDigitalOrder call
    • Closing the instance
    • Taking an encrypted DR (Digital Receipt)
    • Creating a PaymentClient Instance
    • Then use the getDigitalOrder called to decypt it.
    • Invoking the SET wallet
    • Closing the instance

For further information refer to the in-code documentation and the Payment Client Manual.
