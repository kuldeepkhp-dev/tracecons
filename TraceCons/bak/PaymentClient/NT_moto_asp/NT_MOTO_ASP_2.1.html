ASP Integration Examples

This is an example of an ASP integration to the Payment Client for the MOTO Payment Gateway.

MOTO stands for Mail Order Telephone Order and describes 2 party transactions where the merchants already have the customers' Credit Card details and wish to transmit them securely to the Payment Server. This allows for batching of transactions.

Before you start

Step 1. The following assumptions are made:

    • The Payment Client has been installed with COM registration
    • Your web server is configured to use ASP and COM. (This is the default for Microsoft IIS).
    • You have Administrator privileges for your computer
    • Your merchant record at the Bank has the following configuration:
      • Merchant granted privilege 'moto'.

Step 2. You will need the following information prior to the install:

    • ASP file directory (c:\Inetpub\wwwroot)

Installing ASP integration examples

Step 3. Running the Installshield
    • Execute the file .\NT_moto_asp\setup.exe
    • At the prompts enter the information you have gathered at Step 2

Step 4. Running the ASP example
    • Once the installation of the ASP Payment Client Interface is complete you should be able to run the example that uses the ASP Interface. The following URL will demonstrate the interface: http://localhost/MOTO_Order.asp

How to use the examples in your Shop & Buy

Before to integrate into your Shop & Buy it is important to understand the message flow of the files contained within the package. Once the MOTO_Order.asp file's form is completed, the following steps occur:
    • The form submits the field values to MOTO.asp.
    • This file will make calls to the Payment Client, which takes care of encryption and messaging to the Payment Server.

NOTE : For the integrator much of this logic is hidden. The ASP source is well documented to show the basic method of initializing a payment.

Logical flow through an MOTO Payment process:

    • Creating a Payment Client instance
    • Sending a sendMOTODigitalOrder call
    • Closing the instance

For further information refer to the in-code documentation and the Payment Client Manual.
