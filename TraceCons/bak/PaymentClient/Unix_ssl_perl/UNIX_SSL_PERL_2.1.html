Perl Integration Examples

This is an example of a Perl integration to the Payment Client for the SSL+ Payment Gateway.

Before you start

Step 1. The following assumptions are made:

    • You have Perl installed on your server
    • Your Web Server is configured to use Perl/CGI
    • You have installed the MIME-Base64 Perl module
    • You have a Java Runtime Environment installed on your server
    • You have permissions to create directories and execute shell scripts (root user is recommended)
    • The Payment Client has been installed

Step 2. You will need the following information prior to the install:

    • Payment Client installation directory
    • Web Server cgi-bin directory (eg. /home/httpd/cgi-bin)
    • Perl executable directory (eg. /usr/bin/Perl)
    • Perl scripts directory
    • HTML file directory (eg. /home/httpd/html)

Installing the MIME-Base64 Perl Module

The MIME-Base64 Perl Module is not included with Perl by default. This module is required on your system for the Perl integration examples to function. If you do not have this module then you will need to install it now. You may skip this step if the MIME-Base64 Perl Module is already installed.
    • Download the MIME-Base64 module from the Comprehensive Perl Archive Network (CPAN) http://search.cpan.org/
    • Search for the MIME-Base64 package ("MIME::Base64")
    • Take the latest version of this package. Our testing was done on the package "MIME-Base64-2.11.tar.gz"
    • Unpack the component (eg tar -xzf MIME-Base64-2.11.tar.gz)
    • Then follow the instructions indicated in modules readme file

Installing Perl integration examples

Step 3. Running the shell script
    • Copy the "UNIX_SSL_PERL_2.1.tar.gz" file into a temporary directory
    • Untar the "UNIX_SSL_PERL_2.1.tar.gz" file (eg. tar –xzf UNIX_SSL_PERL_2.1.tar.gz)
    • Run the installation shell script "PerlInterface.sh" (eg. sh PerlInterface.sh)
    • At the prompts enter the information you have gathered at Step 2

Running the Perl Interface

Step 4. Running the PCThread listener

    • To start using the Perl interface the "PCThread.sh" script must be run. This initiates a listener thread for the Perl to address. This listener thread is initiated by typing "PCThread.sh" at the command prompt regardless of current working directory. It is recommended that this be added to your environment startup processes. The full path of PCThread.sh is /sbin/PCThread.sh

Step 5. Running the Perl example
    • Once the installation of the Perl Payment Client Interface is complete and the listener thread is running, you should be able to run the example that uses the Perl Interface. This should be able to start from the following URL: http://localhost/SSL_Order.html

How to use the examples in your Shop & Buy

Before integrating into your Shop & Buy it is important to understand the message flow of the files contained within the package. Once the SSL_Order.html file's form is completed, the following steps occur:

    • The form submits the field values to SSL_DO.cgi (DO - stands for Digital Order).
    • This cgi will make calls to the PaymentClient.pl which marshalls the calls across a socket to the Java components of the Payment Client. This is the reason for the other Perl scripts to maintain this socket connection.
    • The java component of the Payment Client takes care of encryption and messaging to the Payment Server.

NOTE : For the integrator much of this logic is hidden. The CGI scripts are well documented to show the basic method of initializing a payment.

Logical flow through an SSL Payment process:

    • Creating a PaymentClient instance
    • Sending a getDigitalOrder call
    • Closing the instance
    • Taking an encrypted DR (Digital Receipt)
    • Creating a PaymentClient Instance
    • Then use the getDigitalOrder called to decypt it.
    • Closing the instance

For further information refer to the in-code documentation and the Payment Client Manual.
